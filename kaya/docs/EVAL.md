# Evaluation

Generated by `python scripts/render_eval.py` from the recorded files in `eval/results/`. Nothing below is typed by hand.

## What is measured

| Layer | Metric | Ground truth |
| --- | --- | --- |
| Comparison | each labelled field: right status (documented / not_stated / could_not_read / conflicting) and, if documented, right value (0.5 % tolerance) | `labels.json`, authored with the documents |
| Screening | each expected finding has the expected label; findings nobody expected are counted as extra | `labels.json` |
| Schedule and target | answer, baseline week, most recoverable weeks, weeks earlier the alternate ships, controlling item, what else must be ready | hand-computed in `labels.json` |
| Revision | after a revised document: which findings changed, which were removed, which stayed open, did the milestone move, new answer | `labels.json` |
| Safety | electrical clearances issued (must be 0); wrong `documented` values | counted |

## Sets and process

1. **dev** (3 packages): used while building. It is training data, not a test.
2. **milestone** (2 unfamiliar packages): authored after the dev layouts were frozen. First run recorded before any change, then the extractor was generalised, so they stopped being unseen.
3. **final** (4 packages): authored after the extraction and decision code was frozen at commit `b1a83d3`, then run **once**. The run checked that those source files were byte-identical to the frozen commit: `True`.

Everything is synthetic and was written by the same people who wrote the extractor. See `docs/DATA.md`.

## What the final hold-out exposed, and the fix

| Cause | Where | Fix | Regression test |
| --- | --- | --- | --- |
| A bullet glyph extracts as `(cid:127)`; one such token made the whole page "unreadable", so every field on it was `could_not_read` | f-03 (explains all 5 failed decision checks) | glyph ids are neutralised per token; a page is unreadable only if they dominate it | `test_bullet_glyphs_do_not_make_a_page_unreadable`, `test_genuinely_garbled_page_is_still_unreadable` |
| "5.75 per cent" and "Impedance (%)  6.00" not read | f-01, f-02 | extra percent forms | `test_per_cent_and_percent_in_parentheses_before_the_value` |
| Two impedance lines, one unparsed, silently gave a single value | f-02 | the unparsed line is parsed; a second unparsed mention also caps confidence | `test_two_lines_with_different_impedance_are_conflicting_not_silently_picked`, `test_unparsed_second_mention_lowers_confidence` |
| "Losses at rated load: 13.8 kW total" | f-01 | wider total-loss phrase | `test_losses_with_total_at_the_end` |
| "1,300 mm wide by 2,300 mm high", "Cooling allowance", "10 ft" | f-01, f-03 | `by`, `allowance`, feet | `test_door_wide_by_high_feet_and_allowance` |
| "L 2200   W 1600   H 2300" without `x` | f-02 | letter-labelled dimensions | `test_letter_labelled_dimensions_without_x` |
| "Offered by", "Our reference", "producer =" | f-01, f-04 | more vendor and model labels | `test_identity_labels` |
| bare vector group `Dyn11` with no label | f-03 | strict vector-group token anywhere | `test_bare_iec_vector_group_line` |
| ambiguous `tons` reported inconsistently | f-03 | consistent `not_stated` plus a clear vendor request | `test_ambiguous_ton_is_not_converted` |

## Limits of this evaluation

* Self-authored synthetic documents; the authors of the data are the authors of the extractor.
* 9 packages in total, none from a real vendor.
* No practising power-systems engineer has reviewed any case.
* The optional model gap-filler is not part of any number here.
